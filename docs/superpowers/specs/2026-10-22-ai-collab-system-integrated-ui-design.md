# AI 协作模块系统一体化界面设计

> 本文保留为 AI 协作模块的视觉一体化基线。团队 Agent 工作台的功能边界、系统架构、数据模型和分阶段实施方案以《[2026-10-22-team-agent-workbench-design.md](2026-10-22-team-agent-workbench-design.md)》为准。

- 日期：2026-10-22
- 状态：设计已确认，待编写实施计划
- 影响范围：团队空间 AI 协作模块、AI 协作交互 Demo、相关公共状态样式
- 不包含：首页、社区、竞赛、成果展示、个人中心等页面的整体重做

## 1. 背景

现有 AI 协作交互 Demo 已覆盖 Agent 会话、执行计划、动作确认、协作文档、协作表格和日常杂活，但 Demo 使用了一套独立的顶栏、左侧工作台、卡片与状态样式，视觉上像一个脱离 iLink 的新产品。

用户确认本轮不是重做全站，而是让 AI 协作设计保持系统一致性：

- AI 协作是团队空间中的一个工作面板，不是独立应用。
- 页面外壳、字体、间距、组件和状态反馈必须继承 iLink 现有团队空间。
- 只有 Agent 特有的会话、计划确认、文档画布和表格画布可以增加专用结构。
- 已确认的明亮状态色应成为统一语义色，不在 AI 模块内部另造一套颜色。

## 2. 目标

1. 保留现有 AI 协作能力和交互流程。
2. 消除 Demo 中与全站脱节的独立页面外壳和视觉令牌。
3. 建立 AI 协作模块与团队空间现有组件之间的明确映射。
4. 提升信息层级、阅读节奏、组件状态和响应式表现。
5. 确保后续接入正式 `team-space.html` 时无需再维护第二套视觉系统。

## 3. 非目标

- 不重做共享页头、页脚和全站导航。
- 不对所有业务页面做结构调整或重新排版。
- 不改变任务、成员、资料、群聊、权限或 AI 接口的数据结构。
- 不把 Demo 的模拟保存、邀请、审计行为直接当作真实后端能力。
- 不引入新的前端框架或组件库。

## 4. 设计原则

### 4.1 系统原生

AI 协作必须表现为团队空间的一个工作面板：

- 外层继续使用 `il-header`、`main-content`、`workspace-layout` 和团队侧栏。
- AI 面板继续位于 `#ai-panel`，不复制全站顶栏或第二个团队导航。
- 内容区使用现有页面背景、表面层级、圆角、边框和阴影强度。

### 4.2 一个动作只有一个主焦点

- Agent 会话是主内容焦点。
- 当前执行计划与待确认动作是次焦点。
- 团队数据与审计信息降低对比度，作为上下文存在。
- 左侧导航、右侧指标和能力入口不得同时使用高对比度强调。

### 4.3 状态先语义、后颜色

- 颜色不能单独表达状态。
- 成功、警告和错误必须同时包含图标或文字。
- 绿色只表示在线、选中、通过、完成。
- 黄色只表示临期、等待确认、需要注意。
- 红色只表示错误、逾期、危险操作。

### 4.4 页面特色服从系统规则

首页古诗词、竞赛目录、成果详情和团队工作台可以保留各自版式特色，但 AI 协作模块的按钮、输入框、标签、弹窗和提示必须与当前系统一致。

## 5. 系统继承边界

### 5.1 直接复用的系统能力

| 能力 | 系统来源 | AI 模块用法 |
| --- | --- | --- |
| 页面顶栏 | 共享页头片段 | 原样使用，不复制 |
| 团队侧栏 | 团队空间导航 | “AI 协作”作为当前面板 |
| 页面容器 | 团队空间主内容区 | 保持现有宽度与左右留白 |
| 按钮 | 全站 `.btn` 体系 | 确认、取消、撤销、导出 |
| 表单控件 | 全站 input/select/textarea | 对话输入、文档编辑、表格单元格 |
| 状态标签 | 全站 badge/status 规则 | 执行中、待确认、成功、失败 |
| 弹窗 | 全站 modal 规则 | 权限、删除、名称冲突确认 |
| Toast | `Toast` 公共组件 | 成功、错误、加载和撤销 |
| 动效与焦点 | 全站 tokens | 悬停、按下、键盘焦点、减弱动效 |

### 5.2 AI 模块新增的专用结构

只允许以下新增结构：

- Agent 会话消息与执行步骤。
- 执行计划卡和逐项动作确认。
- 待确认动作与撤销入口。
- 文档协作画布。
- 表格协作画布。
- Agent 产出的审计记录。

这些结构必须使用系统现有排版、按钮、表单和状态规则，不定义新的品牌颜色或独立外壳。

## 6. 状态色系统

三种明亮状态色作为共享语义色使用，AI 模块不再维护局部近似色。

### 6.1 状态基准色

- 成功、在线、选中：翡翠绿 `#00A86B`
- 警告、临期、等待确认：琥珀金 `#F2A900`
- 错误、逾期、危险操作：亮珊瑚红 `#E64B4B`

### 6.2 小面积浅色底

- 成功浅底：`#E9F8F1`
- 警告浅底：`#FFF6E3`
- 错误浅底：`#FDECEC`

### 6.3 可读文字色

状态色用于图标、圆点、描边和小面积强调。用于小字号文字时使用对应深色：

- 成功文字：`#087A50`
- 警告文字：`#9C6500`
- 错误文字：`#B92F2F`

所有状态组件必须通过对比度检查，颜色不得作为唯一识别方式。

## 7. 布局设计

### 7.1 正式页面布局

AI 协作接入正式团队空间后：

- 页面顶部继续使用共享 iLink 页头。
- 页面主体继续使用团队空间侧栏和主内容区。
- `#ai-panel` 内部采用“Agent 主会话 + 执行上下文”布局。
- 桌面端 Agent 会话约占可用宽度三分之二，执行上下文约占三分之一。
- 会话区与执行上下文都位于现有工作面板内部，不再各自成为独立应用卡片。
- 文档和表格画布在当前 AI 面板内部展开，不跳转到另一个视觉系统。

### 7.2 信息层级

1. 当前团队与竞赛上下文。
2. Agent 身份、模式和工作状态。
3. Agent 会话正文。
4. 下一步建议和快捷能力。
5. 待确认动作与审计信息。
6. 输入区。

### 7.3 空状态

- 首次进入显示 Agent 欢迎语、团队快照和六个能力入口。
- 空状态在空间充足时可垂直居中。
- 内容高于可视区时必须从顶部开始并可完整滚动。
- 用户发送第一条消息后，欢迎区折叠为普通会话历史，不继续占据整屏。

### 7.4 文档与表格画布

- 画布头部使用系统按钮和返回规则。
- 文档正文采用适合阅读的最大宽度，避免超宽屏行长过大。
- 表格工具栏、状态选择、添加行和导出按钮使用系统控件。
- 画布内不出现新的品牌标识或全站顶栏。

## 8. 排版与组件规格

### 8.1 字体

- 继承全站字体栈与中英文规则。
- 正文以 `14px` 为基准，行高约 `1.7`。
- 欢迎区主标题使用系统大标题尺度，不使用营销页巨型字号。
- 辅助信息最小为 `12px`，不再大量使用 10–10.8px 的过小文字。
- 数字、日期和进度使用等宽数字。

### 8.2 表面与圆角

- 页面表面、次级表面、悬停底色沿用现有系统令牌。
- 普通组件圆角保持系统卡片的 `12px` 档。
- 只有小标签和小按钮使用更小圆角，不额外引入装饰性胶囊。
- 阴影只用于输入框、浮层、弹窗和真正离开页面的元素。

### 8.3 导航选中

- 当前“AI 协作”沿用团队侧栏现有选中样式。
- 不增加独立黑色大块导航或 AI 专属侧栏。
- 选中状态必须有文字、形状或位置变化，不仅依赖颜色。

### 8.4 能力卡

- 使用团队空间卡片表面与边框。
- 图标、标题、短说明形成固定层级。
- 悬停只提高边框和表面层级，不做大幅位移。
- 点击后显示按压和加载状态。

### 8.5 输入区

- 输入区视觉与团队群聊输入框同源。
- 焦点状态使用系统焦点环。
- 发送按钮是输入区唯一高对比主按钮。
- 多行输入自动增长，但设置最大高度并内部滚动。

## 9. 交互设计

### 9.1 Agent 模式

- “只读”和“可执行 · 需确认”使用系统分段控件。
- 切换模式立即更新输入区和动作区的权限说明。
- 只读模式仍可分析、生成预览和创建未保存草稿，但不能执行写操作。

### 9.2 执行流程

1. 用户选择能力或发送请求。
2. Agent 展示执行步骤和将读取的数据范围。
3. Agent 给出结果和逐项动作计划。
4. 用户勾选、取消或忽略动作。
5. 用户点击确认后执行。
6. 系统展示执行结果、审计记录和撤销入口。

执行步骤必须显示真实状态：等待、执行中、完成、失败。禁止只使用整个面板的统一透明加载。

### 9.3 反馈

- 成功：使用全站 Toast、绿色完成标记和结果摘要。
- 警告或需要确认：使用黄色状态图标和明确动作按钮。
- 错误：保留用户输入，显示具体原因和重试入口。
- 可撤销动作：结果卡内保留撤销按钮，直到失效或用户离开。
- 所有 Toast 不遮挡共享页头。

### 9.4 动效

- 悬停与状态切换：约 `140–180ms`。
- 卡片展开和画布切换：约 `180–240ms`。
- 支持 `prefers-reduced-motion`，减少位置移动和非必要缩放。

## 10. 响应式规则

沿用团队空间现有断点，不另建一套。

### 10.1 宽屏桌面

- 保留完整团队侧栏和 AI 内部双栏。
- 会话正文限制最大可读宽度。

### 10.2 中等桌面与平板

- 在现有窄屏断点下压缩侧栏和执行上下文。
- 指标与待确认动作可以下移，但不能覆盖会话或输入区。

### 10.3 手机

- 团队侧栏继续使用现有抽屉式操作。
- AI 内部改为单列：会话、动作、团队上下文顺序排列。
- 输入区在进入会话视图时保持可见。
- 文档和表格画布使用单列工具区。
- 页面不得产生横向滚动。

### 10.4 低高度窗口

- 页面外壳允许正常滚动。
- Agent 消息区内部滚动，输入区固定在工作面板底部。
- 欢迎内容高于可用空间时按正常文档流从顶部显示。

## 11. 可访问性

- 所有按钮必须有可见焦点状态。
- 图标按钮必须有 `aria-label`。
- 执行计划勾选项必须可键盘操作。
- 动态执行状态通过 `aria-live` 播报。
- 错误提示与对应字段或动作建立可理解关联。
- 触摸目标不小于约 `40px`，小屏优先满足 `44px`。
- 状态信息不只依赖颜色。

## 12. 视觉一致性验收

将 AI 协作页面与团队空间其他面板并排检查：

1. 页头完全相同，不出现第二个顶栏。
2. 页面背景、主内容宽度和左右留白一致。
3. 团队侧栏导航位置、宽度和选中规则一致。
4. 标题、正文、辅助文字的字号与行高来自同一套层级。
5. 按钮、输入框、标签和弹窗在同等状态下外观一致。
6. 卡片圆角、边框、阴影强度与团队空间其他面板一致。
7. 绿色、黄色、红色在同一语义下与全站一致。
8. AI 模块独有结构看起来是业务扩展，而不是另一个产品。

## 13. 功能与响应式验收

1. Agent 六个能力入口均可触发对应流程。
2. 只读与可执行模式切换正确。
3. 动作勾选、确认、忽略、执行、撤销和审计状态正确。
4. 文档编辑、邀请展示、保存反馈正常。
5. 表格编辑、完成度计算、添加行和 CSV 导出正常。
6. 成功、警告、错误和加载反馈明确且不遮挡页头。
7. `1440px`、`1280px`、`1024px`、`768px`、`390px` 下无横向溢出。
8. 低高度窗口下输入区仍可见，消息区可内部滚动。
9. 键盘可完成模式切换、能力选择、动作勾选和确认。
10. 首页及其他非目标页面不发生布局或组件结构调整；更新共享状态语义色时，仅同步颜色，不重新排版。

## 14. 实施边界

- 交互 Demo 只承担方案验证，不替代正式团队空间。
- 正式接入前保持现有后端接口和权限行为不变。
- 新样式优先通过共享语义令牌和现有组件扩展实现。
- 如必须新增 AI 专用变量，统一使用 `--il-agent-*` 前缀并限制在 AI 面板作用域。
- 禁止在 AI 模块内复制一套独立颜色、按钮、输入框、弹窗或 Toast。
