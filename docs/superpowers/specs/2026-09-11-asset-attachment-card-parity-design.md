# 成果详情附件卡片一致性设计

## 目标

将成果详情页的附件展示改为与交流社区文章详情页一致的紧凑卡片，消除当前附件独占整行、文件信息与下载按钮分离的问题。

## 范围

- 修改成果详情页附件列表的 DOM 结构、样式和点击下载交互。
- 复用现有 `window.ILinkFiles.iconMarkup()` 生成文件类型图标。
- 保持现有原始文件名解析、下载接口、未登录拦截和下载计数逻辑不变。
- 不修改交流社区附件卡片，不改变成果附件的数据结构和上传流程。

## 视觉与交互

- 单张卡片桌面端宽 `168px`，宽高比 `21:13`，与社区附件卡片一致。
- 附件列表使用横向流式排列并自动换行，一行可容纳多个文件。
- 卡片由文件类型图标、原始文件名和“点击下载”提示组成。
- 文件名保持单行，超长时省略；完整名称通过 `title` 提示查看。
- 移除右侧独立“下载”按钮，整张卡片作为下载链接。
- 悬停、边框、背景和排版状态与社区附件卡片一致。
- 窄屏下卡片最大宽度不超过容器，不产生水平滚动。

## 实现方式

成果详情脚本生成语义化下载链接卡片，并为附件卡片使用成果页专属类名。成果详情样式按社区卡片的尺寸和视觉参数实现，避免改动已稳定的社区模块。点击委托改为识别成果附件卡片链接，继续执行未登录提示和登录跳转。

## 异常与兼容

- 缺少原始文件名时继续使用现有友好文件名回退逻辑。
- 未识别扩展名时显示通用文件图标。
- 无附件时继续隐藏整个附件区域。
- 下载地址仍由现有 `/api/asset/download/{id}` 接口提供，下载文件名继续由服务端响应头控制。

## 验收标准

1. 成果详情附件卡片与社区详情附件卡片在尺寸、结构和状态上保持一致。
2. 整张卡片可点击下载，页面不再显示独立下载按钮。
3. 文件类型图标正确，原始文件名正确，长文件名不会撑开布局。
4. 桌面端一行可显示多个附件卡片，窄屏不溢出。
5. 登录用户可以下载；未登录用户仍收到登录提示并跳转登录页。
6. 无附件成果的页面展示不发生变化。
