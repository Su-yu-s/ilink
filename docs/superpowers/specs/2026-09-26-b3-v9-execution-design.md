# B3 v9 优化执行方案（执行口径锁定版）

日期：2026-09-26。状态：用户已确认实施；本稿锁定最后评审口径，留出独立封存通过前禁止继续代码修改。

## 1. 范围、依据与当前状态

沿用 2026-09-23 的证据驱动设计，落实用户对 v9 方案的十项评审意见。B1 为普通文档 RAG；B2 为固定两跳局部 GraphRAG；B3 为项目使用的 Agentic GraphRAG。先确认三者实现符合定义，再比较回答效果，不保留有缺陷的弱基线。

本轮固定 v8 的共享数据快照、100 题和生成/Embedding 模型。快照报告为 261 实体、230 关系、151 片段，graphHash 前缀 6626db75；执行时必须读取 manifest 的完整 hash 验证。算法、评测工具的变更分开记录。图谱重建和向量库迁移另立实验。

v8 三轮 E+T+M 为 B1 49/50/51、B2 39/38/35、B3 45/44/45（满分 65）。B3 的 E 为 19/20/19，T 为 21/20/20，M 为 5/4/6，U 为 32/32/35。总分接近 B1 尚不能证明可答问题能力接近。此前审计只覆盖通过答案，结论限于受审答案，不能宣称编造问题根治。

已有部分代码修复草稿通过单元测试，尚无 v9 正式三轮结果。当前源码包含历史和后续未提交修改，不能把 git HEAD 等同于 v8 的实际源码版本。本稿不把预算限制、权限补强、留出封存等描述为已经实现。

## 2. 目标、里程碑和止损

### 2.1 指标层次

- 主质量指标：E+T+M，固定分母 65；U 单独作为合规回归约束。保留 100 题总分及原验收目标的判定。
- 分项里程碑：E 追平同条件 B1；T 追平同条件 B2；M 不低于同条件较强基线。用开发小批量观察方向，用正式完整分项成绩判定是否完成。
- 最终既定目标：三轮总分均严格高于 B1/B2；同时三轮主指标均严格高于 B1/B2。平分记为未达成“优于”。总分、主指标、合规、成本、泛化分别显示，不能互相抵消。
- U 约束：每轮不少于 32/35，三轮合计不少于 99/105，且每轮不低于同轮 B2；任何真实权限泄露、证据不足的定向事实推荐均为独立缺陷。32/99 是沿用 v8 表现的工程门槛，不是统计显著的非劣界值。
- 可靠性约束：无无效引用、无确认的无证据事实断言、无权限泄露；完整性单独计分。没有发现问题应表述为“本次审计未发现”，不推广为普遍保证。

### 2.2 分阶段门槛

| 阶段 | 内容 | 进入下一阶段的条件 |
|---|---|---|
| P0 | 独立留出立即封存；随后版本锁定、基线机制检查、权限回归、题集与量表登记 | 独立封存是本次确认后首次代码修改的前置；封存通过后完成其余正确性、权限、预算计量检查 |
| P1 | 路由、协议、引用、截断修复 | 固定 20 题中目标错误减少；E+T+M 不低于前一个开发候选；无新增事实或权限缺陷 |
| P2 | 原文和多主体补检 | E 子集不低于同轮 B1；主体覆盖提升；预算达标 |
| P3 | 事实与完整性双校验 | 校准集误拦/误放门槛通过；完整性错误减少；U 哨兵无持续回退 |
| P4 | 时序及聚合 | T 子集不低于 B2，M 子集不低于较强基线；分页完整性与权限检查通过 |
| P5 | 候选冻结后的三轮评测 | 按 2.1 逐项判定；不在三轮中途修改实现、阈值和评分器 |

候选实验定义为：改变算法、检索/校验策略或提示词，冻结候选版本并对固定 20 题运行三算法评估。明确 bug 的修复不占候选名额，但必须有预先可复现的失败、确定的行为契约和针对性回归；扩展问题覆盖、调整阈值、提示词或检索权重不能改名为 bug 修复规避计数。bug 修复及其在线验证仍登记版本、消耗总实验预算，共享组件修复后仍须同轮重跑三算法。

每个 P1–P4 阶段最多两次候选实验，所有结果保留。以进入该阶段前已验证的 B3 版本为固定参照，在 20 题中的 16 道 E/T/M 上计算正确题数差。连续两次“提升 ≤1 题且成本超过上限”定义为低收益超预算，自动撤回该阶段新增机制。成本本身是独立门槛，质量提升不能抵消超预算；两次候选后仍不满足阶段条件即停止该阶段，不增加第三次候选。撤回后运行此前有效部分的回归测试，确认基准行为恢复。小样本成本只用于预警，正式完整轮成本按第 5 节验收。

正式任一轮主指标低于 B1，立即记录“稳定优势未达标”。在安全和费用约束允许时仍按预注册完成剩余轮以报告波动；权限泄露、确认的严重事实错误、预算异常可提前终止，明确终止原因，不能删掉失败轮。v9 默认只进行一套正式三轮；进一步候选另起版本，不能从多套结果中挑最好三轮。

未达标时交付已验证收益、剩余错误及数据缺口，不自动降低原目标，也不自动以其他叙事替代验收。

## 3. 证据需求规划：规则为主、受约束的模型补充

### 3.1 输出契约

QueryEvidencePlan 增加可验证字段：subjects（问题中的主体文本及偏移）、requestedAttributes（所问属性及偏移）、operation（事实/列表/比较/交集/计数/推荐）、timeWindows、requiredEvidenceKinds、coverageMode、unresolvedReasons。只有问题明示的数量才能进入 expectedCount；没有明示则为未知。

计划不包含答案、臆造实体 ID 或未经验证的事实。主体先提取文本，再经有权限的实体检索消歧。用户身份、权限范围和数据库条件由服务端确定，模型不能改写。

### 3.2 生成流程

1. 规则处理明确日期、单位、属性、并列主体、列表/比较/交集触发条件；使用既有日期解析组件，优先验证边界语义。
2. 规则无法解析的多主体/复杂操作，最多调用一次规划模型；使用当前冻结生成模型、严格 JSON schema，输出上限 384 tokens。v9 不额外引入未经验证的小模型和模型版本变量。
3. 校验字段枚举、跨度是否真的来自问题、日期是否合法、主体/子查询上限。拒绝没有原文跨度的新增主体和模型臆造的预期答案项。
4. 无效或模糊计划回退到原问题的有权限原文检索；不能因为规划失败直接编造关系、强制套用步骤模板或跳过权限。

### 3.3 独立的规划标注验证

准备 80 条规划样例：50 条开发、30 条锁定验证，覆盖属性、别名、并列主体、时序、比较/交集、不可答和模糊问题。规划标签只描述问题意图，不携带标准答案；标注由项目评审者核定。与最终 40 题留出集隔离。

进入主流程的初始门槛：主体/属性跨度 F1 ≥90%；必需证据类型召回率 ≥95%；完整计划匹配率 ≥85%；新增不存在主体为 0。另用确定性边界测试要求已支持日期格式全部正确。报告原始分子、分母及每类错误，不能只给宏观百分比。

锁定验证集仅用于规划候选验收一次；若查看失败样例继续调规则，该集转为开发集，后续泛化结论不能继续使用它。达不到门槛则保留已验证规则路径，关闭模型规划补充。

## 4. 原文与图谱融合、冲突与停止条件

### 4.1 检索与上下文

- 每题最多 4 个主体子查询，包含首轮和补检的新 query；多个时间窗口最多 2 个。超出上限的请求保留未覆盖清单，返回有依据的部分，不静默声称已全部回答。
- 原文首轮 top-k=8，去重后按问题相关性和主体覆盖挑选；优先复用现有检索，不引入需要训练的新重排器。
- 仅当片段存在未结束的列表、跨片段句子、指代缺上下文或所问字段明显位于同段后续时补邻片段。每个命中文档最多补前/后各 1 块，全题邻片段新增最多 4 块，仍受工具与 token 总预算限制。
- 证据上下文默认 2,000 tokens，最大 3,000 tokens；计入模型输入总账。优先保留每个主体的证据，再补共同属性、关系与时间；使用原文句段及偏移，不把生成摘要当成原始事实。
- 单条事实的数字与单位、列表项、关系端点与有效期不可切开。完整证据台账留在服务端，每轮只注入当前相关证据和简短行动记录；不重复注入全部工具 JSON。
- 完整性要求得到满足、达到邻块/查询预算、连续两次实际检索无新增可用事实或来源时停止补检。补检最多 1 个定向循环，循环内按主体调用但不突破总上限。

### 4.2 冲突规则

比较前先对齐实体、属性、适用时间和文档版本。两个不同时间的值不自动判为冲突。

- 图谱抽取事实必须能回到来源。原文明示与对应抽取字段不一致时，标记抽取冲突，采用可定位的原文明示回答文档属性，并保留冲突记录。
- 明确询问图谱关系或路径时，只认真实关系记录，不能把原文提及补造成图谱边。
- 权威性、时间和版本无法消解的源文档冲突，不按相似度或“最新入库”强选；并列说明有证据的冲突或返回不确定。
- 时序夹具与真实资料的来源性质保留在证据中；不能把夹具的历史关系推断成现实竞赛日期。

## 5. 预算与降级

下列为 v9 的拟定成本验收线及初始配置，P1–P4 只能在这些上限内调整调用和上下文参数；正式三轮开始前冻结。数字是验收约束，不是已实现性能。若确需提高成本线或降低 U 门槛，须在独立的方案修订中说明代价并由用户确认，不能根据正式成绩临时放宽。

| 项目 | 初始约束 |
|---|---|
| 每题累计聊天 tokens | 平均目标 ≤6,000；正式每轮均值硬门槛 ≤6,500；P95 ≤14,000 |
| 单题总请求预算 | 16,000 tokens 硬调度上限；调用前做输入上界+最大输出的原子预留，预算不足不发起，触顶立即中断，不允许为了补答、重试或回退扩大预算 |
| 模型输入中的证据 | 默认 2,000、最大 3,000 tokens；不含系统提示和动作 schema，但它们计入总账 |
| 每题模型调用 | 总计最多 10 次，包含 ReAct 决策最多 5、规划最多 1、答案生成最多 1、校验最多 1、改写最多 1、余量最多 1；余量只供改写复核或一次故障重试，不能突破 ReAct 5 次；所有实际请求计入 |
| 工具执行 | 最多 8 次实际执行；分页请求和重试均计入；缓存命中单独记录，不重置预算 |
| 单次输出上限 | 规划 384；动作 256；语义校验 512；答案/改写 1,200 tokens |
| 修复循环 | 最多 1 轮定向补检和 1 次答案改写；校验失败的答案不绕过门槛发布 |
| 延迟 | 每轮均值 ≤12 秒；P1/P2 基础修复与补检 P95 ≤30 秒，P3/P4 及正式完整性校验版 P95 ≤35 秒；单题请求截止时间 45 秒，向 HTTP/DB 子调用传递剩余超时 |

工具执行与模型决策分别计数。程序首轮按既定计划预取证据无需模型决策；一次经校验的决策可以产生同一计划内的有界工具批次。8 次工具上限不代表必须进行 8 次 ReAct 决策，不强制用满任一预算。模型每次实际 HTTP 请求只归入一个阶段并计入总数；若一次决策同时给出最终答案，该次仍计入 ReAct，后续独立生成可省略。未使用配额不能挪成第 6 次 ReAct。

累计聊天 tokens 严格采用供应商 usage 的 prompt_tokens + completion_tokens 全量求和，包含规划、ReAct、生成、校验、改写、复核、重试及回退中的所有模型请求；不能扣除命中的缓存输入或漏计模型思考 tokens（供应商包含于 completion 时不重复加总）。在线语义校验成本同时计入主账并分项展示。Embedding 调用次数/tokens、检索耗时另列；离线评分和审计独立记账。基于相同口径与 v8 的 4,780 聊天 tokens 比较。B2 同轮成本比值作为报告项，不能以旧 B2 成本代替新基线。均值/P95 包含超时、失败与预算中断题；P95 固定采用 nearest-rank 定义。

16,000 的硬中断在发起调用前执行：已结算 usage + 在途预留 + 本次输入保守上界 + 最大输出不得超过 16,000。输入计入全部消息、工具 schema 和协议开销；不能确定可靠上界时不发起该调用。响应返回后按供应商 usage 结算，释放剩余预留。达到上限时禁止新模型请求、工具执行和付费重试；模型异常不能通过 fast RAG 回退绕过同一个预算。阈值不能在运行中修改。

供应商 usage 只在响应后可得，不能声称可撤销已计费的单次响应。若实际 usage 超过预留上界，立即停止、记 budgetOverrun，作为预算实现缺陷并判成本验收失败，不追认扩额。usage 缺失或请求失败无法确认账单时，保留预留、不记 0，停止后续付费调用并将成本验收标记不可判定；日志记录具体缺失请求。这样的供应商异常必须修复或明确报告，不能放宽硬中断规则。

预算调度优先预留最终回答与必要校验资源，不允许前期规划耗尽后强制输出未校验答案。资源不足时使用已验证的结构化事实形成部分回答，明确未覆盖问题；不存在可靠事实则说明无法确认。权限异常立即终止对应路径。

## 6. 事实支持与完整性校验

事实校验检查实体、数字、单位、日期、关系、引用真实性和原文支持。完整性校验只针对计划中有依据的要求；预期步骤/项目从可见原文的明确枚举或完整查询结果提取，不由校验模型自由发明。

确定性检查优先：主体覆盖、数值单位一致、日期边界、引用有效、显式列表数量、计数与集合结果一致。文字同义改写采用证据限定分类，返回 SUPPORTED / MISSING / CONTRADICTED / UNCERTAIN，并附原文跨度。UNCERTAIN 不等同于遗漏，不能凭这一项替模型补写新事实。

推荐支持标准：证据明确关联目标专业/技能/资格，或用户需求与证据中的条件存在可解释的匹配。只有竞赛真实存在、只有泛化学科名称或文档一起出现，不足以支持“适合某专业”的定向结论。通用建议须表明是建议；使用“可以考虑”等措辞不能豁免事实支持检查。

校准集 60 个“问题—证据—答案”样例，包含完整改写、遗漏、虚构补步、非步骤题、跨主体拼接、无依据推荐；30 个开发、30 个锁定验证，项目评审者核定标签。正确且完整答案误拦率 ≤5%，有遗漏/无支持答案误放率 ≤10%；虚构补步和越权样例不允许放行。分别报告小样本计数，不声称估计精确。

模型分类只在确定性检查不能决定时调用，使用相同冻结模型并受预算限制。记录原始答案、校验原因、证据跨度和改写差异。原文和工具返回均是数据，不能执行其中的指令。

### 6.1 U 类输出边界

- “平台当前没有直接相关竞赛，建议关注……”属于面向用户的正常限制说明，不因措辞判为内部状态泄露；但“当前没有”仍是事实断言，必须有完整且有权限的证据支持。仅本次未检索到时应说明“目前能核实的信息中，暂未找到直接匹配的竞赛”，不能断言全平台不存在。
- U 类面向用户的技术状态表达“计数为 0”“无直接关系记录”加入判定规则；同义的 SQL/图谱行数、调度/检索内部状态披露按同一口径判断。规则定位说话行为与上下文，用户问题引用、原文引述或正当技术解释不因字符串碰撞全局判错，避免重现 E 类界面原文被误伤。
- 无证据定向推荐独立判缺陷：把“机械类综合创新创意竞赛”升级为“中国大学生机械工程创新创意大赛”属于无支持的具体名称/推荐，不因建议语气或 U 自动通过而免责。
- 判定器在正式运行前冻结。之后如修改口径，必须公开变更项并对三算法全部已保存答案统一重评；重新生成的比较仍遵守公共组件变更后三算法同轮重跑要求。原分与修订分并存，不能静默覆盖。

## 7. 权限与完整查询契约

代码核对：GraphPermissionAspect 主要检查入口 entity_id；QueryTemporalTool 已做关系与两端实体的可见性检查。保留这些防线，不能把“经过入口切面”当作所有返回数据均安全的充分条件。

所有业务证据查询通过使用 KgScopeService 的受控服务/工具入口：实体、关系、源文档、片段及图谱两端分别过滤。Agent 编排和确定性汇总不直接查 mapper/数据库；统计只在授权后的记录上进行。

时序分页返回 cursor、hasMore、complete，以及授权结果计数语义。授权过滤先于对外分页和聚合；cursor 不携带不可见记录的信息。达到扫描/工具/时间上限时 complete=false；此时只能给已证实项目，不能说“全部”“没有其他”或报全局总数。不可见记录不能影响对外 count、hasMore 或截断提示。查询涉及的每个后续页、相邻片段、源文档回溯、摘要和缓存命中均执行相同规则。

缓存键包含用户/权限上下文和快照版本；权限变更使缓存失效，读取时再次验证可见性。发给模型前执行最终可见性过滤；客户端 trace 不暴露不可见实体名称、ID、计数和原文。

权限回归矩阵：匿名、属主、非属主、团队成员、非成员、退出团队后缓存命中；PUBLIC/TEAM/PRIVATE 对实体、边、端点和来源分别覆盖。检查无 entity_id 的全局时序、多跳、分页、计数/交集、相邻块、回退和改写路径。安全测试使用隔离夹具，不修改正式冻结快照。

## 9. 分层审计及费用上限

- 正式 100 题三轮的 B3 全量 300 答案进行证据对照审计，包括自动判错答案。每个审计包包含问题、答案、chunk/relation/entity 引用及可见来源、适用时间、自动判分；隐藏算法名称及是否通过，减少先入判断。
- B1/B2 各每轮分层抽 15 个：E5/T4/M3/U3，总共 90 个答案。按预先固定随机种子 20260926 抽取，报告纳入概率；风险驱动样本单列，不能混为总体无偏错误率。
- 额外优先审计“自动判错但证据可能正确”、定向推荐、时间/数值矛盾、关系缺来源等高风险基线答案，最多加 30 个。默认正式阶段审计上限 420 个答案包；B3 的 300 不抽样。
- 留出阶段全量审计 B3 40 个，B1/B2 各分层抽 10 个（E3/T3/M1/U3），基础 60 个；高风险基线最多追加 20 个。正式加留出默认上限合计 500 个答案包。
- 超出风险复核上限时，审计状态为未完成并报告需要扩大的范围，不能把剩余风险默认为通过。模型审计每包至多一次初审、一次争议复核；证据过长按断言拆包，拆包也占审计预算并单独计费。

标签：supported（所问事实有支持且必要覆盖完整）、partial（已有事实获支持但漏项或范围不清）、unsupported（断言无支持/冲突）、audit_input_incomplete（缺失引用或来源无法读取）。最后一类是审计基础设施问题，修复后重审，不能直接算算法编造。

无支持定向推荐按第 6 节的明确标准判定。任何真实关系、存在的竞赛名称都不能自动为定向适用性背书。纯建议和平台事实逐条区分。

审计员以已核定的校准样例统一标准。规则/模型执行的全量审计称为机器证据审计；人工复核所有争议和高风险断言，并抽查至少 10% 的 B3 supported 答案，人工复核复用既有包。没有人工参与不得写“人工全量核查”；争议未解决则审计门槛未通过。固定人力不足时报告限制，不把另一模型同意当成人工结论。

## 10. 预注册统计规则

主分与总分分别逐轮报告，同时给 E/T/M/U。错误及超时进入分母；基础设施异常按预先定义的统一恢复规则处理，不能只重试 B3 的失败题。默认不在正式运行中用额外采样挑选更好答案。

对 E+T+M 的每题、每算法取三轮通过比例 p_i（0、1/3、2/3、1）。主效应为 65 题上 B3 与基线 p_i 差的均值，换算百分点；三轮分别领先仍是工程验收门槛。

描述性不确定性：按 E/T/M 分层，以题目 ID 为单位抽样 10,000 次，每次携带该题所有算法的三轮结果，使用种子 20260926，报告配对差的百分位 95% 区间。不会把 195 个可答结果当作 195 道独立题；同来源题目仍可能相关，解释时说明其限制。

合并 McNemar：每题每算法至少两轮通过记为多数通过，形成 65 个配对二元结果；B3 对 B1、B2 分别做双侧精确 McNemar，两项 p 用 Holm 校正。逐轮六项检验和合并两项检验全部报告，附两侧不一致题数；逐轮检验仅作描述，不从中挑一个 p<0.05 宣称整体显著。多数通过的检验与通过比例均值衡量不同目标，两者都报告，不混用。

已有 100 题参与过调参，因此上述 p 值和区间只描述这套开发题上的差异，不作为未经选择的泛化证据。留出一次运行只在 26 道 E/T/M 上做预注册双侧精确 McNemar（两基线 Holm 校正），效应区间沿用按题目配对、按 E/T/M 分层的 10,000 次 bootstrap，此时每题只携带一轮结果；U14 单独报告。样本小导致检验功效有限，未显著不等于等效，工程达标也不自动等于统计显著。

留出验收：B3 在 26 道可答题上分别优于 B1/B2，U 至少 13/14 且不低于 B2，事实/权限审计通过。是否达到统计显著作为独立结论，不以达到显著为由增加运行次数。开发目标达成但留出失败，应如实标注泛化验收未通过。

留出整体定位为方向性泛化检查；尤其 M 只有 4 题，仅报告逐题证据和通过数，不宣称 M 类强统计显著。bootstrap 次数固定 10,000、种子固定 20260926，正式运行后不能更换种子寻找更有利区间。
