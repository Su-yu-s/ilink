# B3 证据驱动 Agentic GraphRAG 优化设计

日期：2026-09-23

## 目标与边界

B1 是普通 RAG，B2 是 GraphRAG，B3 是基于 iLink 项目优化并应用于项目的 Agentic GraphRAG。B1、B2 是对比算法，但它们的检索、证据、引用和权限语义也必须正确。本轮先把三种算法实现到各自定义的正确状态，再在同一套 100 题、同一冻结语料快照和同一模型配置下对比；此后持续优化 B3，使其在重复运行中稳定优于 B1、B2，并减少无依据的实体、关系、日期、文档和技术细节。结果必须如实报告；设计不预设 B3 必然胜出。

本轮包含 B1 普通 RAG 实现、B2 GraphRAG 正确性修复、B3 问答流程、证据与原文回溯、图谱重建、评测和可见性一致性。不改用户界面，也不针对题号或金标答案编写检索规则。现有未提交改动应保留，实施提交不得混入无关文件。

## 当前证据

- 第三轮 100 题中，E+T+M 主指标 B2 为 19/65，B3 为 7/65；B3 平均耗时 18.9 秒，B2 为 9.1 秒。
- B3 收到 `Final Answer` 后立即返回，没有检查该类问题所需证据是否已取得。无格式输出也会被当作最终答案。每轮最多执行一个工具，因此 5 轮上限通常早于 12 次工具上限生效。
- 当前引用列表从工具观察文本中抓取 ID，未检验答案中的 ID、实体名、关系、时间和事实是否得到支持。现有判定器仅在答案含 `#ID` 且引用列表为空时拦截。
- `get_document` 只返回文档类型和 ID，不返回标题或原文片段；实体搜索只返回实体描述。细节未被抽取时，B3 无法回到原文求证。
- 现行 100 题评测代码只运行 B0/B2/B3；B1 尚未作为该批次的可复现基线实现。B2 的子图文本未包含关系有效期，不能把其 T 类得分解释为直接读取时间窗。
- 报告中的部分工具调用计数与批次 JSON 不一致：E/T/M 中仅一次 `search_entities` 是 26 题；T 类未调用 `query_temporal` 是 17/25。后续诊断统计由原始结果自动生成。

## 方案选择

1. 只修改 ReAct 提示词：改动小，但无法阻止模型跳过工具，也无法验证事实。
2. **采用：证据驱动的 B3**。程序负责最低限度的证据准备和最终校验，ReAct 负责自适应选择后续工具与搜索路径。
3. 只提升图谱抽取质量：会改善所有方法的输入，但不能单独解决 B3 的早收束和编造。

先完成三种算法的正确性门槛，再实现方案 2 的 B3 优化，然后改数据并重建共享快照。每阶段分别评测，以便归因；最终三种算法在重建后的同一快照上复测。

## B3 问答流程

### 1. 查询意图与最低证据门槛

新增独立的查询规划组件，输入为用户原始问题与初次检索结果，输出所需证据类型和下一步动作。规则只使用问题文本与工具结果，不读取评测题的 E/T/M/U 标签、题号或金标。

| 问题特征 | 回答前最低证据 |
| --- | --- |
| 单点实体属性 | 命中目标实体；具体细节须有对应实体描述或来源片段 |
| “哪些、列举、关联、包含、共同”等关系或聚合问题 | 对目标实体执行邻居/关系展开；答案中的每项须对应可见的边或来源事实 |
| 明确年月、日期、时间段或历史状态 | 解析时间窗并执行 `query_temporal`；不得用当前邻居关系代替历史关系 |
| 原文细节、方法名、数值、引句、帖子标题 | 读取带来源标识的原文片段 |
| 无法定位证据 | 可给通用建议，但不得编造平台记录或把建议表述成平台事实 |

规划规则采用保守触发。若初次分类不确定，ReAct 可继续探索；一旦模型提出最终答案，程序检查最低证据门槛。未满足时继续调用相应工具，不能直接返回。时间窗解析失败或实体定位不确定时，工具返回明确的结构化状态供规划器改写查询；不得猜测 ID。

### 2. 自适应探索与预算

保留六工具 ReAct 机制，并增加原文片段读取能力。将“模型轮数”和“工具调用次数”分别计量；最低证据准备可批量执行，不占用仅供模型决策的轮数。设定明确的总耗时、上下文和调用预算，超限时基于已有证据生成保守答案。重复的同工具同参数请求直接复用结果。工具观察以结构化数据保存，不以截断字符串作为唯一事实来源；给模型的历史可摘要，但答案校验使用完整、可见的原始证据。

### 3. 证据清单与答案校验

新增每次查询独立的证据清单。每条证据保存来源类型、实体/关系/文档 ID、可见性范围、原文或结构化事实、时间范围以及工具调用来源。证据清单只接纳工具成功返回且当前用户可见的记录；工具错误和模型生成文本不能成为证据。

最终生成先形成带证据引用的事实陈述，再渲染给用户。确定性校验包括：答案中出现的实体 ID 属于本次证据集；名称与对应 ID 一致；关系两端、类型和时间窗与已取回关系一致；文档 ID 与来源映射一致。具体技术细节和原文引句必须能指向来源片段。对于无法机械核验的改写事实，可用独立的证据支持判定步骤标记为“支持/不支持/不确定”，不确定视为未获支持；该步骤的效果由人工抽检验证。

校验失败时只重写一次，并把失败点反馈给生成器。仍不通过时删除无依据的具体事实，只输出已核实内容或可执行的通用建议。不得为了满足“直接回答”要求凭空补全平台私有事实。对用户的答复继续遵守现有不暴露内部检索状态的表达规则；内部轨迹记录证据不足和校验失败原因。

引用列表从最终答案**实际使用**的证据生成，不再从全部观察文本中正则抓取。B3 的非降级路径与回退路径均执行相同的答案校验和权限规则。

## 数据与工具

### 原文片段索引

以现有索引任务保存的标题、正文和 `docType/docId` 为源，建立可重建的文档片段索引。片段保存标题、正文范围、源文档 ID、可见性范围和 Embedding；中文技术名、数值、代码标识符保留原样。片段检索支持向量与关键词混合召回，并返回来源和位置。B1 使用该片段索引的 top-k 作为普通文档 RAG；B3 可沿实体到文档映射回溯片段，也可在实体检索不足时直接搜索片段。B2 使用实体检索、固定 2 跳图扩展和子图生成；其正确性问题必须修复，不能为了让 B3 获胜保留缺陷。

原文读取须在片段、源文档和实体层检查可见性。B1、B2、B3 在相同用户身份下只接收其有权访问的材料；实施时修正目前 B2 未使用 `userId` 过滤的路径。评测同时保留权限隔离用例。

### 图谱抽取与重建

抽取提示词要求保留原文明确出现的方法名、机制名、数字、单位、标题日期和关键事实，不把另一文档事实拼入同名实体。关系和实体增加来源定位，使答案能回到原文。时间字段只根据源文档明确的事件生效期填写，文档入库时间不能充当历史事件时间。抽取结果经过类型、来源和格式检查后写入。

创建版本化迁移和可重复运行的重建流程；不修改已执行的 V33 迁移。重建前备份图谱及索引表并记录实体、关系、文档、片段数；重建完成后按评测脚本重新装载合成时序边，再冻结带版本号的快照。重建与评测期间不得让后台索引任务改变该快照。若重建失败，恢复备份并保留失败日志，不使用半成品快照评测。

## 对照评测

### 三种算法的正确性门槛

三种算法分别验证其定义，不用最终得分代替实现正确性：

| 算法 | 必须验证的行为 |
| --- | --- |
| B1 普通 RAG | 文档切片可追溯到真实原文；top-k 检索和关键词兜底有序、去重、权限过滤；生成只引用实际取回的片段；无命中时不编造平台私有事实 |
| B2 GraphRAG | 入口实体检索、两跳扩展、关系方向和端点正确；子图含回答所需的实体名、关系类型及有效期；历史关系按问题时间窗解释；引用与实际子图一致；所有实体和边符合当前用户可见性 |
| B3 项目 Agentic GraphRAG | 继承正确的图谱、文档与权限语义；关系、时序、细节题达到最低证据门槛；工具调用结果与最终事实逐项对应；预算、失败和降级路径不绕开校验 |

公共答案契约要求三种算法都不输出不存在的来源 ID，不把未检索到的内容说成平台事实，并在证据不足时给出保守回答。可以共用引用格式、权限过滤和输出校验基础设施，但 B1 不借用图扩展，B2 不借用 B3 的自适应规划；各算法的方法差异保持清楚。用确定性的检索与权限测试、构造的时序边界测试、来源对照测试和少量人工事实审查作为进入正式对比评测的门槛。发现 B1/B2 缺陷时先修复并重新冻结基线版本，再测 B3；不得使用有缺陷的弱基线宣称优势。

### 基线与固定条件

- B1：普通文档片段 RAG；B2：固定 2 跳 GraphRAG；B3：基于 iLink 优化的证据驱动 Agentic GraphRAG。B0 可保留为下界，不参与“超过 B1/B2”的主目标。
- 三者使用同一源语料快照、用户身份、生成模型版本、Embedding 模型版本和题目文本。记录每次运行的模型参数、温度、快照版本、检索参数、token、耗时、答案和来源。
- B1 的片段索引和 B2/B3 的图谱由同一冻结语料构建；各方法可以使用其定义所需的数据表示。控制答案风格与可见性规则，避免因接口提示词差异造成明显偏置。
- 每个阶段保存独立结果目录和不可覆盖的运行标识。既有 `round2_batch*.json` 只作历史基准，不再覆盖。

### 指标与验收

三种算法通过各自正确性门槛后，主指标才比较 E+T+M 的逐题正确率；U 类合规通过率单列。另报每类正确率、配对胜负、延迟、token、工具调用、时序工具覆盖率、关系展开覆盖率、无依据实体/关系/文档/事实数，以及答案引用可追溯率。判定器不仅检查要点词，还检查答案引用 ID 属于实际证据；人工盲审重点复核编造及“命中关键词但事实错误”的答案。判定器改动与旧规则分开报告，不回写历史分数。

同一套 100 题完整独立运行三次。目标是 B3 每一轮的 E+T+M 正确率均高于 B1 和 B2，且零个越界引用 ID；三轮分别报告配对检验，不能把重复题当作 300 道独立题合并检验。人工复核样本中的无依据具体断言必须显著少于旧 B3，并报告样本量与剩余错误。增加不参与设计调参的盲测题，检查对 100 题的过拟合。若目标未达到，按失败类别继续迭代，不把不显著或不干净的命中宣称为胜利。

由于现有 `AiClient` 将温度固定为 0.3，先使温度可配置且在三基线中保持一致；重复运行用同一温度与模型版本。评测脚本必须实际运行 B1，不能用 B0 或旧竞赛答疑结果代替。

## 实施顺序与验证

1. 固定旧结果与数据快照，建立源文档片段索引，补 B1 普通 RAG 和评测运行标识；修复 B2 的方向、时间、引用和可见性问题，验证 B1/B2 的算法门槛与共同答案契约并冻结正确的对照版本。
2. 实现 B3 查询规划、证据清单、原文回溯和最终答案校验；使用模拟工具结果测试关系、时序、细节、无结果、错误与权限场景，并运行现有单元测试，使 B3 也通过其算法门槛与共同答案契约。
3. 在**旧图谱**上对正确的 B1/B2 与优化后的 B3 重跑，测量算法层改动带来的增量，重点确认不再搜索一次就回答关系题。
4. 完成抽取改进和版本化迁移；备份、重建图谱与片段索引、装载时序数据并冻结新快照，重新通过三种算法的正确性门槛。
5. 在新快照上按统一条件运行 B1/B2/B3 三轮；自动汇总，人工盲审编造案例，发布原始结果和限制说明。后续只针对 B3 的真实失败模式继续迭代，每轮保持正确基线与条件一致。

设计获批并形成实施计划后再修改生产代码或数据库。任何实际分数提升都以复测结果为准。
