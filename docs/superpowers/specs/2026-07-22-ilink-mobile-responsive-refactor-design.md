# iLink 全站移动端响应式重构设计

日期：2026-07-22
状态：待用户复核
方案：B — 整理并重构现有样式体系，不新增末尾补丁层

## 1. 目标

在不改变后端接口、请求参数、权限判断和业务流程的前提下，为 iLink 的全部运行页面建立一致的桌面、平板、移动端和小屏布局。重构同时消除当前重复加载、重复媒体查询和互相覆盖的导航规则，保证桌面端现有效果不回退。

覆盖范围包括：

- 首页、组队大厅、导师招贤、交流社区、竞赛目录、成果展示；
- 详情页、发布页、登录注册、法律说明、404 与错误页；
- 团队空间、看板、团队详情与团队聊天；
- 文章编辑/发布、成果编辑/发布及 Markdown 预览；
- 个人中心概览、资料、成果、文章、收藏、密码和公开主页；
- 管理后台只做响应式兼容回归，不改变其信息架构。

## 2. 不变约束

1. `> 1024px` 的内容、视觉层级、交互入口和页面宽度保持现状；重构前后使用截图和 computed style 对照验证。
2. 不修改 Controller、Service、Mapper、数据库迁移、API URL、HTTP 方法、请求体和响应解析。
3. 不重写现有数据加载、身份权限、发布、申请、任务状态和附件上传逻辑。
4. 只允许为响应式交互增加展示层状态，例如抽屉开关、看板移动端状态 Tab、编辑/预览模式和拖拽禁用判断。
5. 保留用户已打磨的首页内容、诗句、区块顺序与桌面动画；移动端仅调整布局、尺寸和动效强度。

## 3. 当前问题

- 共享导航同时存在右侧抽屉、三列导航和底部 Tab 三套移动实现，后加载规则会隐藏汉堡菜单。
- `components.css`、`style.css`、`app-redesign.css` 和页面 CSS 重复定义相同组件与断点。
- 多数页面重复加载 `app-redesign.css`；部分模板还在页面内写内联样式。
- 断点混用 1200、980、960、920、768、720、640、576、430，导致 721–767px 仍可能显示多列。
- `profile.css`/`profile-redesign.css`、`team-space.css`/`team-space-redesign.css` 职责重叠。
- Markdown 编辑器没有完整移动规则；Kanban 在手机上仍是横向四列且启用拖拽。
- `overflow-x: hidden` 被用来遮住超宽元素，不能证明页面真的没有溢出。

## 4. 样式架构

重构后的职责固定如下：

| 文件 | 唯一职责 |
| --- | --- |
| `design-tokens.css` | 色彩、字体、间距、圆角、阴影、层级和公共尺寸变量 |
| `layout.css` | 页面容器、主栅格、通用侧栏和 1024/768/480 布局规则 |
| `components.css` | 导航、按钮、表单、卡片基础、Toast、Modal、标签等共享组件及其状态 |
| `effects.css` | 可关闭的装饰动画、减少动效和触摸设备动效降级 |
| `style.css` | 仅保留尚未迁走的全局兼容规则；不再定义导航和页面专属响应式布局 |
| `app-redesign.css` | 仅保留全站主题外观，不再重复组件结构或断点 |
| `search-bar.css` | 全站搜索、筛选和操作区；只保留一套响应式实现 |
| 各页面 CSS | 页面独有的结构、卡片变体和页面断点 |
| `md-editor.css` | Markdown 工具栏、编辑/预览布局和 Markdown 内容防溢出 |

执行时采用“迁移一块、删除一块”的方式，不在文件尾追加同选择器覆盖。`profile-redesign.css` 与 `team-space-redesign.css` 中仍有效的规则分别并回主文件后停止加载；公共门户共享规则保留在单一公共文件中。未使用的 `home-redesign.css` 在确认无引用后删除。模板中重复的 redesign 引用和内联页面样式一并清理。

## 5. 断点与公共布局

- 桌面：`min-width: 1024.02px`，保留当前布局。
- 平板：`min-width: 768px` 且 `max-width: 1024px`，页面 padding 24px，主要网格 2 列，侧栏改为可折叠或顶部导航。
- 移动：`max-width: 767.98px`，页面 padding 16px，单列、全宽、触摸优先。
- 小屏：`max-width: 479.98px`，卡片 padding 16px并微调字号。

宽度正好 768px 明确按平板处理。页面不能依赖 `overflow-x: hidden` 掩盖问题；只有标签、工具栏、表格和代码块等内部容器允许横向滚动。

## 6. 共享导航

六个公开页面和其他带全站头部的页面继续只使用 `fragments/header.html`。

- 桌面端保持当前导航样式。
- `< 768px` 时头部固定为 56px，并计入 `env(safe-area-inset-top)`。
- Logo 左对齐，右侧仅保留通知/头像和 44×44 汉堡按钮。
- 点击汉堡后，导航抽屉从右侧滑入，遮罩为 `rgba(0,0,0,.4)`；菜单垂直排列，字号 16px。
- 当前页面入口使用已有 `activeMenu` 高亮。
- 登录/注册或个人中心/退出入口放在抽屉底部独立区域。
- 点击链接、遮罩或 Escape 自动关闭；同步 `aria-expanded`、`aria-hidden`，关闭后将焦点还给汉堡按钮。
- 停用并移除底部 Tabbar、Mobile More Panel 和首页专属导航分支。

导航脚本只管理展示状态，不发请求、不改变路由。

## 7. 页面与组件适配

### 7.1 搜索与筛选

- 移动端输入框独占一行并为 100% 宽。
- 筛选器在 480–767px 尽量两列，小于 480px 时单列。
- 搜索、发布等操作按钮放在独立操作行，间距 8px，触摸高度至少 44px。
- 已经无实际用途的重置按钮不重新引入。
- 社区和竞赛标签横向滚动、保持单行并隐藏滚动条。

### 7.2 内容卡片

- 组队、导师、成果在移动端单列；竞赛为桌面 3 列、平板 2 列、移动 1 列。
- 移动卡片 padding 20px，小屏 16px；标题 18px；导师头像 40px。
- 社区标准卡片保持 `20px 24px`，小屏收口为 16px；操作按钮一行，阅读全文换行并为 100% 宽；封面高 160px。
- 触摸设备取消 hover 上浮和复杂阴影，使用边框、轻阴影和 `:active` 反馈。

### 7.3 团队空间与 Kanban

- 平板看板为 2 列，侧栏可折叠。
- 移动端隐藏固定侧栏，提供“项目菜单”抽屉，展示原有导航与团队信息。
- 看板以“待办 / 进行中 / 待审核 / 已完成”状态 Tab 切换，一次显示一列；列标题可 sticky。
- 移动端任务卡设置为不可拖拽；长按打开现有任务操作能力的底部菜单，用现有更新、编辑和删除函数完成动作。
- 负责人可见的创建任务入口改为右下角 56px FAB，并处理底部安全区。
- 桌面拖拽与四列布局保持原样。

### 7.4 编辑器与 Markdown

- 移动端默认纯编辑模式，禁用分栏按钮，但允许切换预览。
- 工具栏单行横向滚动，按钮至少 44px；编辑器输入字号 16px。
- 编辑区和预览区 padding 16px；附件入口成为带安全区的底部 sticky 操作区。
- 代码块内部滚动、字号 13px；表格在自身容器内滚动；图片最大宽度 100% 并保留圆角。
- 桌面端分栏、拖动分隔线、保存和上传流程不变。

### 7.5 个人中心

- `profile.html` 改用共享 `profile-sidebar` fragment，消除唯一的硬编码副本。
- 平板侧栏可折叠；移动端转换为顶部横向滚动 Tab，滚动条隐藏但保留滚动能力。
- 表单控件宽度 100%、高度至少 48px、字号 16px。
- 弹窗、Toast、通知面板和关闭按钮满足 44px 触摸尺寸并处理安全区。

## 8. 资源和性能

- 列表、卡片和非首屏内容图片补充 `loading="lazy" decoding="async"`；首屏 Logo、当前用户头像和编辑器即时预览不强制懒加载。
- `prefers-reduced-motion: reduce` 关闭非必要动画。
- `(hover: hover) and (pointer: fine)` 才启用 hover 上浮；触摸设备只使用 active 反馈。
- 不引入新的前端框架或第三方响应式依赖。

## 9. 验证方案

### 9.1 静态与构建检查

- 搜索重复 CSS 引用、重复共享组件选择器和不符合三档规范的关键断点。
- JavaScript 语法检查与 Maven 全量测试。
- 验证本次 diff 不包含 Java 后端、Mapper、SQL 和 API 路径改动。

### 9.2 桌面回归

在 1280px 或更宽视口，对核心页面保存重构前后截图，并比较：

- 导航高度、容器宽度、主网格列数；
- 首页诗句、区块顺序和动画入口；
- 按钮、卡片、搜索栏和表单 computed style；
- 发布、申请、收藏、编辑、任务状态等入口仍可达。

### 9.3 设备回归

使用 Playwright + Chrome 分别测试：

- iPhone SE：375px；
- iPhone 14 Pro：393px；
- iPad Mini：768px；
- 平板上界：1024px；
- 桌面保护：1280px。

逐页断言：

1. `documentElement.scrollWidth <= clientWidth + 1`；
2. 375/393px 为单列，768/1024px 为规定的平板布局；
3. 可见交互元素宽高不小于 44px，移动表单字号至少 16px；
4. 抽屉开关、当前项高亮、遮罩、Escape 和点击后关闭正确；
5. Kanban 移动端一次只显示一个状态，拖拽关闭，FAB 可见；
6. 编辑器默认单栏，可切换预览，代码/表格/图片不撑宽页面；
7. 个人中心 Tab、Modal、Toast、通知和附件区打开后仍无溢出；
8. 浏览器控制台无新增错误，关键网络请求的 URL、方法和响应处理未改变。

## 10. 实施顺序与回退边界

1. 保存桌面和三种目标设备的基线截图与 DOM 指标。
2. 整理共享加载顺序与导航，完成一次全站冒烟测试。
3. 按公开页、团队空间、编辑器、个人中心四个批次迁移并删除重复规则。
4. 每完成一个批次立即运行桌面与设备回归，不累积到最后统一排错。
5. 最后执行全量功能测试和逐项需求审计。

若某次迁移导致桌面 computed style 或关键交互变化，只回退该组件的样式迁移，不回退已验证的其他批次；不通过增加更高优先级补丁掩盖问题。
