# 高校竞赛协作平台团队 Agent 工作台设计

- 日期：2026-10-22
- 状态：方案已确认，待用户复核
- 毕设选题：基于 Agentic GraphRAG 算法的高校竞赛协作平台设计与实现
- 影响范围：团队空间 `#ai-panel`、Agent 会话与动作中心、团队知识检索、任务协作接口
- 不包含：首页、竞赛目录、社区、成果展示、个人中心的整体重做

## 1. 结论

将现有“AI 智能答疑 + 任务拆解”升级为团队 Agent 工作台，不构成选题偏离。

工作台不是独立于 iLink 的通用办公产品，而是高校竞赛协作平台中的团队协作入口。Agentic GraphRAG 仍是知识检索、多轮推理、证据校验和可追溯回答的核心算法；工作台负责组织上下文、展示执行过程、承载用户确认并连接平台已有业务动作。

论文与答辩中统一使用以下定位：

> 面向高校竞赛团队协作场景，设计以 Agentic GraphRAG 为知识检索和推理核心的团队 Agent 工作台。

不得将平台描述为“基于大语言模型的通用 Agent 工作台”，也不得让文档、表格等通用办公能力取代 GraphRAG 的核心地位。

## 2. 当前基础

### 2.1 已真实实现

| 能力 | 当前实现 | 设计用途 |
| --- | --- | --- |
| 快速问答 | 固定两跳 GraphRAG | 回答简单的知识、关系和文档检索问题 |
| 深度问答 | Agentic GraphRAG，最多 5 轮、8 次工具调用、45 秒 | 处理多跳、时序、跨文档和需要补充证据的问题 |
| 推理过程 | SSE 推送工具调用、观察结果和最终答案 | 在工作台中显示可审计的“执行记录” |
| 引用回溯 | 实体引用、来源文档和实体详情 | 验证团队建议和竞赛结论的依据 |
| 权限过滤 | GLOBAL、TEAM、PRIVATE 三类可见范围 | 防止团队和个人数据越权进入回答 |
| 任务拆解 | 生成建议，用户勾选后创建真实子任务 | 作为 Agent 动作规划的第一个落地能力 |
| 团队周报 | 本地聚合任务状态和截止日期 | 提供可靠数字，AI 仅负责后续组织和表达 |

### 2.2 当前不足

1. 团队空间问答请求没有显式绑定当前团队，检索范围是用户可访问的全部团队。
2. 团队使用自定义竞赛名称时，AI 只识别竞赛目录 ID，无法正确绑定该竞赛。
3. 页面隐私说明声称只发送公开竞赛信息，但实际可能读取用户可见的团队任务等数据，说明与实际范围不一致。
4. Agent 问答只保存单次推理轨迹，没有会话、上下文延续和消息历史。
5. 不存在独立的 Agent 动作记录、执行结果、撤销和审计模型。
6. Demo 中的协作文档、表格、自动排期、催办、归档等能力没有正式后端与持久化。
7. 团队资料库尚未进入知识图谱索引，任务编辑和删除后也没有刷新已有索引。
8. 成员接口没有返回完整技能数据，当前不能真实地按技能和负载自动改派任务。
9. 工作台仍由问答卡和任务拆解卡两个独立区域组成，没有统一上下文、待确认动作和执行记录。
10. AI 区域仍有小字号、蓝紫色轨迹和其他页面不一致的样式，内嵌实例的部分专用样式未生效。

## 3. 目标与非目标

### 3.1 目标

1. 在团队空间内建立统一、连续、可验证的团队 Agent 工作台。
2. 将 GraphRAG 检索、团队结构化数据和业务动作统一到同一 Agent 流程。
3. 明确当前团队、竞赛、用户角色和数据读取范围。
4. 对每项写操作执行“方案预览、用户确认、业务执行、结果反馈、撤销或审计”闭环。
5. 保持现有竞赛协作平台的产品身份、导航、视觉和业务边界。
6. 为论文提供可演示、可度量、可解释的算法应用链路。

### 3.2 非目标

- 不把整个平台改造成聊天应用。
- 不开发与竞赛协作无关的通用 AI 办公套件。
- 不允许 Agent 直接读取群聊记录。
- 不允许 Agent 绕过现有成员、任务、导师和团队权限。
- 不把规则明确的统计问题交给大模型计算。
- 不将前端 Demo 的模拟能力写成已实现功能。
- 不在第一阶段承诺多人实时协同文档和表格。

## 4. 核心原则

### 4.1 GraphRAG 是核心，工作台是载体

复杂知识问题必须通过 Agentic GraphRAG 完成多轮检索和证据校验。工作台负责呈现证据、组织动作和承载用户决策，不替代算法本身。

### 4.2 结构化事实优先

任务数量、完成率、截止日期、逾期数量等确定性数据直接查询业务数据库。GraphRAG 用于跨文档、多跳关系、时序事实和需要解释依据的问题，不用于重新计算简单统计值。

### 4.3 写操作必须确认

Agent 可以生成计划、草稿和动作提案，但不能静默改库。每个动作必须经过用户逐项勾选和最终确认。

### 4.4 当前团队优先

团队工作台只能以当前团队为主作用域。用户加入多个团队时，不得把其他团队的私有子图、任务或资料混入当前回答。

### 4.5 证据先于表达

涉及竞赛规则、成员关系、任务来源、历史事实和团队材料的结论必须附来源。无证据时不补写事实，应明确说明信息不足。

### 4.6 系统原生

工作台继续使用共享页头、团队侧栏、按钮、表单、弹窗、Toast、字体和状态语义，不复制第二套应用外壳。

## 5. 总体架构

```text
┌──────────────────── 团队空间现有页面外壳 ────────────────────┐
│ 共享页头 + 团队侧栏 + 当前团队上下文                          │
│                                                              │
│ ┌──────────────── Agent 工作台 ────────────────┐             │
│ │ 上下文条：团队 / 竞赛 / 角色 / 数据范围       │             │
│ │                                               │             │
│ │ ┌──────────── Agent 会话 ───────────┐ ┌─────┐ │             │
│ │ │ 用户目标                         │ │团队 │ │             │
│ │ │ 执行计划与证据                   │ │态势 │ │             │
│ │ │ 动作提案                         │ │待确认│ │             │
│ │ │ 输入框                           │ │记录 │ │             │
│ │ └──────────────────────────────────┘ └─────┘ │             │
│ └───────────────────────────────────────────────┘             │
└──────────────────────────────────────────────────────────────┘
```

### 5.1 上下文层

`TeamAgentContextService` 聚合当前团队、竞赛、用户、角色、任务、成员、资料和审核状态。

上下文必须包含：

- `teamId` 与团队名称。
- 当前用户 ID、角色和团队权限。
- 目录竞赛 ID 或团队自定义竞赛名称。
- 团队状态、截止日期和成员数量。
- Agent 本次允许读取的数据类别和数量。
- 当前是否为队长、导师、任务负责人或普通成员。

上下文构建由后端完成，前端只负责选择竞赛和展示范围摘要，不能通过篡改前端参数扩大权限。

### 5.2 Agent 决策层

Agent 根据目标选择两类工具：

1. 知识工具：实体检索、文档检索、邻居扩展、关系原文、时序查询、实体过滤和社区摘要，继续复用 Agentic GraphRAG。
2. 业务工具：任务读取、成员与技能读取、竞赛信息读取、团队资料元数据读取、周报聚合。

Agent 不获得任意 SQL、任意 URL 或通用系统命令。业务工具全部由独立的 Spring 服务封装，并在入口校验团队成员身份。

### 5.3 动作层

Agent 的业务写操作先生成结构化动作提案：

- 创建任务。
- 创建子任务。
- 改派任务。
- 调整优先级或截止日期。
- 创建成员提醒。

每条提案包含目标对象、修改前后值、原因、证据、执行人、权限校验结果和过期时间。

用户确认后，由 `TeamAgentActionService` 调用现有任务、通知和审计服务执行。Agent 模型本身不直接执行数据库写入。

### 5.4 呈现层

工作台呈现四类内容：

1. 对话与结论。
2. 可折叠的执行记录。
3. 可勾选的动作提案。
4. 团队态势、待确认事项和最近执行记录。

## 6. 团队作用域与数据一致性

### 6.1 当前团队隔离

团队 Agent 接口必须接收并校验 `teamId`。GraphRAG 业务工具在团队工作台模式下只能读取：

- 当前团队可见的 TEAM 数据。
- 与当前问题相关的 GLOBAL 数据。

第一阶段默认不读取 PRIVATE 图谱数据。确需使用个人资料时，通过经过权限校验的用户资料或成员业务接口读取明确字段，不使用个人知识子图扩大范围。仅使用 `userId` 获取用户全部可见团队的过滤方式不能满足团队工作台要求。

### 6.2 自定义竞赛

团队 `competitionId` 为空且存在 `customCompetition` 时，上下文使用该自定义名称。不得要求用户必须从竞赛目录重新选择一个近似赛事。

### 6.3 知识索引

第一阶段保证团队任务在创建、编辑、改派、状态变更和删除时同步更新或失效其知识索引。

团队资料文件正文索引放入第二阶段。第一阶段只向 Agent 提供文件名、类型、大小、上传者和更新时间等元数据，避免假装已经理解文件内容。

### 6.4 数据可信状态

当知识索引正在更新、失败或过期时，执行记录必须显示“数据可能不是最新”，不得静默给出确定性结论。

## 7. Agent 工作流

### 7.1 只读分析

1. 用户输入目标或选择快捷能力。
2. 工作台显示本次准备读取的数据范围。
3. Agent 选择知识工具和业务工具。
4. Agent 展示执行步骤、来源和结论。
5. 用户可以继续追问或要求生成动作方案。

### 7.2 动作规划

1. Agent 分析当前状态并说明需要改变的数据。
2. Agent 生成逐项动作提案。
3. 工作台显示修改前后值、原因、权限和证据。
4. 用户取消不需要的项目。
5. 用户点击确认。
6. 后端重新校验权限、对象状态和提案有效期。
7. 同一提案组在同一事务中执行并写入审计记录，通知等外部副作用在事务成功后触发。
8. 工作台显示执行结果和可用撤销入口。

### 7.3 撤销

- 每项动作使用幂等键，重复点击确认不会重复创建任务。
- 撤销前检查目标对象是否在提案执行后又被其他用户修改。
- 若已被修改，不覆盖他人的新操作，转为人工处理并说明原因。
- 撤销本身写入审计记录。

### 7.4 失败恢复

- 检索失败时保留用户输入和已完成证据。
- 外部 AI 不可用时明确提示，不生成伪造答案。
- 动作组事务失败时整组回滚，并逐项显示未执行原因，不能显示笼统的成功提示。
- 用户关闭页面后，已确认动作仍由后端完成，结果可在会话中重新加载。

## 8. 第一阶段能力

### 8.1 团队知识问答

- 使用当前团队上下文和竞赛上下文。
- 支持快速与深度两种检索模式。
- 深度模式展示工具调用、证据和最终答案。
- 引用可查看实体、关系来源和原始文档。

### 8.2 团队风险巡检

基于任务、截止日期、负责人、审核状态和成员负载生成风险清单：

- 已逾期任务。
- 七天内到期任务。
- 长时间无状态变化的任务。
- 未分配或负责人异常的任务。
- 审核被驳回但未继续处理的任务。
- 团队截止日期与任务截止日期冲突。

风险结论必须引用具体任务 ID 和字段，禁止只输出泛化建议。

### 8.3 周报

- 数字和任务清单继续由本地聚合接口生成。
- Agent 负责按“进展、风险、下周计划”组织草稿。
- 生成后先预览，用户确认后才发送到群聊或保存。
- 不读取群聊，不把成员隐私信息发送给外部模型。

### 8.4 任务拆解与创建

- 已分配任务仅负责人可发起拆解。
- 未分配任务仅队长可发起拆解。
- 子任务不可继续拆分。
- Agent 建议先预览，用户勾选后才创建。
- 创建动作继续调用现有任务服务，保留通知和审核规则。

### 8.5 任务调整

第一阶段允许：

- 队长确认后创建或改派任务。
- 调整任务优先级和截止日期。
- 向指定负责人创建一次任务提醒。

不允许：

- Agent 自动删除任务。
- Agent 自动通过导师审核。
- Agent 自动解散团队或移除成员。
- Agent 自动修改竞赛正式提交状态。

## 9. 第二阶段能力

### 9.1 协作文档

- Agent 根据用户选择的资料和任务起草文档。
- 文档在团队空间内以工作台画布打开。
- 首版支持自动保存和版本记录。
- 保存后登记到团队资料库的“AI 产出”目录。
- 实时多人编辑与冲突合并不纳入第二阶段首版。

### 9.2 协作表格

- 支持基础单元格编辑、行列增删、状态选择和完成度统计。
- 表格保存为团队内部结构化数据。
- 可导出 CSV 和 Excel。
- 所有由 Agent 预填的数据必须标明来源。

### 9.3 材料对照

实现前必须具备两项真实数据：

- 结构化的竞赛材料要求。
- 可提取正文或明确元数据的团队资料。

缺少任一条件时，只能提供人工核对清单，不得声称已经完成自动材料审核。

### 9.4 导师协作

- 导师可以让 Agent 汇总待批阅任务和风险。
- Agent 可以生成评审检查清单和反馈草稿。
- 审核通过、驳回和评分仍由导师本人确认。

## 10. 界面设计

### 10.1 桌面布局

- 沿用现有共享页头和团队侧栏。
- `#ai-panel` 内使用“主会话 + 执行上下文”两栏。
- 主会话占约三分之二宽度，执行上下文占约三分之一。
- 输入区固定在主会话底部，会话内容独立滚动。
- 不出现第二个产品 Logo、第二套顶栏或“返回平台”入口。

### 10.2 上下文条

顶部显示：

- 当前团队。
- 当前竞赛或自定义竞赛。
- 当前角色。
- 本轮数据范围摘要。

竞赛选择沿用系统输入框规则，可搜索目录竞赛，同时显示团队自定义竞赛。

### 10.3 Agent 会话

- 用户消息使用系统深色中性强调。
- Agent 消息使用普通表面和轻边框，不使用大面积品牌渐变。
- 执行记录默认折叠，展示工具名称、读取范围、耗时和结果摘要。
- 不直接展示模型内部思维文字，将其转换为可验证的“处理步骤”。
- 引用以小型来源芯片展示，点击可查看实体或原文。

### 10.4 待确认动作

每个动作卡包含：

- 动作类型。
- 目标任务或成员。
- 修改前后值。
- 建议原因。
- 证据或数据来源。
- 权限说明。
- 勾选框和确认按钮。

只展示用户有权执行的动作。无权限动作显示为建议，不提供确认按钮。

### 10.5 状态和反馈

- 成功使用系统绿色语义，并同时显示完成图标和文字。
- 等待确认或风险使用系统琥珀色语义。
- 失败、逾期和危险操作使用系统红色语义。
- 取消、过期和无数据使用中性灰。
- 状态不能只依靠颜色表达。

### 10.6 字体与控件

- 正文基准为 14px，辅助文字不小于 12px。
- 标题、正文、数字和标签沿用团队空间现有层级。
- 对话输入框与群聊输入框同源。
- 按钮、下拉框、弹窗和 Toast 使用全站组件规则。
- 移除没有真实业务意义的“重置演示”等控件。

### 10.7 响应式

- 1100px 以下由双栏转为单栏。
- 移动端以标签切换“对话、态势、记录”，输入区始终可用。
- 页面不得出现横向滚动。
- 低高度窗口下会话区内部滚动，输入区保持可见。

## 11. 后端组件

### 11.1 TeamAgentController

负责：

- 加载工作台上下文。
- 加载或创建当前团队会话。
- 接收 Agent 消息并返回 SSE。
- 查询待确认动作和执行历史。
- 确认或撤销动作。

建议端点：

- `GET /api/team/{teamId}/agent/bootstrap`
- `POST /api/team/{teamId}/agent/chat/stream`
- `GET /api/team/{teamId}/agent/conversations/{conversationId}`
- `POST /api/team/{teamId}/agent/actions/{actionId}/confirm`
- `POST /api/team/{teamId}/agent/actions/{actionId}/undo`
- `GET /api/team/{teamId}/agent/actions`

### 11.2 TeamAgentService

负责：

- 构建受限上下文。
- 选择只读工具。
- 生成结构化回答或动作提案。
- 校验证据和动作 schema。
- 持久化消息、动作和结果。

### 11.3 TeamAgentActionService

负责：

- 动作权限重新校验。
- 目标对象状态检查。
- 幂等执行。
- 事务提交。
- 撤销快照。
- 审计记录。

### 11.4 现有 GraphRAG 能力

全局悬浮问答继续使用通用 GraphRAG 入口。团队 Agent 使用独立的团队作用域入口，并在内部调用同一套 GraphRAG 服务和工具。

不得复制两份检索算法，只允许在入口上下文、工具集合和结果处理上分层。

## 12. 数据模型

### 12.1 team_agent_conversation

保存团队会话元数据：

- 会话 ID、团队 ID、创建用户 ID。
- 当前竞赛 ID 或自定义竞赛快照。
- 标题、创建时间、最后消息时间。
- 状态。

### 12.2 team_agent_message

保存消息：

- 会话 ID、角色、正文。
- 回答引用、执行记录摘要和模型状态。
- 创建时间。

不记录聊天已读状态，不新增已读回执。

### 12.3 team_agent_action

保存动作：

- 团队 ID、会话 ID、消息 ID、发起用户。
- 动作类型、目标类型和目标 ID。
- 修改前快照、提案内容和证据。
- 权限结果、状态、幂等键和过期时间。
- 执行结果、失败原因和创建、执行、撤销时间。

`kg_agent_trace` 继续保存单次知识问答轨迹，不承担会话和业务动作审计职责。

## 13. 权限与隐私

1. 所有工作台请求先校验用户是当前团队成员。
2. Agent 工具只能使用当前团队作用域，不接受前端传入任意实体范围。
3. 队长、导师、任务负责人和普通成员使用现有业务权限。
4. 成员技能、资料和任务摘要只向有对应业务权限的用户展示。
5. 群聊内容默认不进入 Agent 上下文。
6. 用户主动粘贴的文本可以作为本轮分析材料，但必须明确标记为“用户提供内容”。
7. 写操作确认时再次校验权限和对象状态。
8. 外部 AI 请求前展示数据范围摘要。
9. 审计日志记录操作者、Agent 版本、输入来源、动作和结果，不保存敏感凭据。

## 14. 论文与答辩映射

| 论文内容 | 系统落点 | 答辩证据 |
| --- | --- | --- |
| Agentic GraphRAG 多轮检索 | 深度问答中的计划和工具调用 | SSE 执行记录、轮数和工具次数 |
| 图谱与原文证据链 | 引用、实体详情、关系原文 | 从答案追溯到原文 |

| 证据门控与降级 | 无证据不臆造、AI 不可用提示 | 失败路径与评测结果 |
| Agent 工具编排 | 知识工具与业务工具协同 | 风险巡检、任务拆解流程 |

## 15. 验证与验收

### 15.1 算法

- 对比普通 RAG、固定 GraphRAG 和 Agentic GraphRAG。
- 评估答案正确性、证据支持率、引用正确率和无依据事实比例。
- 统计轮数、工具调用次数和耗时。
- 验证多跳问题、时序问题和跨文档问题的提升。

### 15.2 安全与权限

- 非团队成员不能加载工作台。
- 当前团队不能读取其他团队私有实体和任务。
- 普通成员不能确认队长专属动作。
- 导师审核仍需导师本人操作。
- 伪造动作 ID、重复确认和过期确认均被拒绝。

### 15.3 功能

- 会话刷新后可恢复。
- 问答、风险巡检、周报、任务拆解均可使用真实数据。
- 动作确认后业务数据真实变化。
- 撤销后数据恢复且审计完整。
- AI 不可用时页面可恢复并保留输入。

### 15.4 界面

- 1440px、1280px、1024px、768px 和 390px 下无横向溢出。
- 键盘可完成输入、展开记录、勾选动作和确认。
- 动态状态使用可访问的实时播报。
- 页面与任务看板、群聊和资料库的视觉规则一致。

## 16. 实施顺序

### 第一阶段：能力收口

1. 建立当前团队上下文与团队作用域 GraphRAG 入口。
2. 修正自定义竞赛、隐私文案和任务索引一致性。
3. 补齐成员技能、任务负载和审核状态上下文。

### 第二阶段：Agent 工作台

1. 建立会话、消息和动作数据模型。
2. 实现风险巡检、周报草稿、任务拆解和动作提案。
3. 接入确认、幂等执行、撤销和审计。
4. 替换团队空间现有双卡片 AI 区域。

### 第三阶段：协作载体

1. 实现团队文档画布和版本记录。
2. 实现结构化表格画布和导出。
3. 增加团队资料索引和材料对照。
4. 根据实际需求评估多人实时协作。

## 17. 完成标准

本阶段方案完成的判断标准不是页面看起来像聊天产品，而是：

1. 用户进入团队工作台后，Agent 能明确识别当前团队、竞赛和角色。
2. 复杂问题使用 Agentic GraphRAG 完成多轮检索并给出可追溯证据。
3. 确定性统计查询来自业务数据库，不由模型猜测。
4. 团队建议能够转成受权限约束的动作提案。
5. 写操作经过确认、真实执行、审计和可用的撤销路径。
6. 会话与动作在刷新后仍可恢复。
7. Demo 能力与正式系统能力有清晰边界，未实现能力不进入正式页面冒充完成。
8. 论文能够用系统流程、代码、测试和演示证明 Agentic GraphRAG 是核心而非包装。
