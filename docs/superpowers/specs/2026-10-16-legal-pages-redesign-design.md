# 隐私政策 / 用户协议页面重做设计

- 日期：2026-10-16
- 状态：已确认（方案 A：左侧粘性目录 + 右侧正文）
- 影响范围：改写 `templates/privacy.html`、`templates/terms.html`；新增 `static/css/legal.css`、`static/js/legal.js`。不修改 `fragments/head-assets.html` 与任何全站共用文件。
- 参考产品：Apple 隐私政策（中文）、Mozilla Firefox 隐私声明（中文）、Stripe 隐私政策、GitHub General Privacy Statement、Linear Terms of Service、Vercel Privacy Notice

## 1. 背景与目标

`privacy.html` 与 `terms.html` 是**全站唯一两个没有任何专属样式的页面**。

实测确认：`.legal-page` 在全站 CSS 中零定义，全部搜索命中只有这两个文件自身的 3 处引用；`data-app-page="legal"` 也没有任何 CSS 或 JS 使用。两页只加载了 `head-assets :: core` 的通用样式，因此呈现的是浏览器默认样式——标题巨大、正文紧贴页面顶部、无卡片、无留白、无导航。

同时内容也过于单薄：每页只有 3 段法律腔的短句，没有回答用户实际会问的问题（我填的信息谁会看到？我的成果版权归谁？平台出问题谁负责？）。

本次目标：

1. 把两页重做成与全站视觉语言一致的正式文档页，采用「左侧粘性目录 + 右侧正文」的成熟产品做法。
2. 把内容从 3 段扩写为各 8 节，用中文平实语言重写，覆盖 iLink 的真实业务机制。

非目标：

- 不改后端接口、路由、权限判断（`SecurityConfig` 中两页仍为 `permitAll`）。
- 不改注册页的协议勾选逻辑与链接文案。
- 不引入法律意见或对外承诺；文案只描述平台**当前已实现**的行为。
- 不给两页添加全站页脚（`fragments/footer.html` 目前仅 `index.html` 使用，加入会造成不一致）。
- 不改动首页受保护内容。

## 2. 优秀产品的共同做法（本次设计的依据）

逐字阅读六家产品的隐私政策 / 服务条款后，提炼出五条被反复使用的原则：

| 原则 | 代表做法 |
| --- | --- |
| 开头一句话讲完整篇 | Apple：「Apple 的隐私政策阐释了 Apple 如何收集、使用和共享你的个人数据。」Mozilla：「我们认为，您理应有权知道自己的数据因何种原因、以何种方式被使用。」 |
| 标题写成用户会问的问题 | Apple：「在 Apple，个人数据是指什么？」「你在 Apple 的隐私权」；Mozilla：「我们会如何使用您的数据？」 |
| 全程用「你」，解释「为什么」 | Mozilla 每节都写「为向您提供 X，我们会处理 Y 数据」，而非「本公司将收集……」 |
| 显眼标注日期与版本 | 六家全部在标题下方标注「最后更新 / 生效日期」（Stripe: June 26, 2026；Apple: 2025 年 7 月 30 日） |
| 结构上做减法 | 该列表就列表（Stripe 的收集项）、该对照表就对照表（Stripe 的定义章节）、该提醒就单独成块，不让用户在大段文字里找重点 |

本次设计逐条采用这五条。

## 3. 页面结构

两页共用同一骨架，只有文案不同。

```
<header>                     全站头部（复用 fragments/header :: header(${currentUser}, '')）
<main class="lg-shell">
  <div class="lg-head">      文档头
    .lg-eyebrow              类型标签（盾牌图标 + 「隐私说明」/「平台规则」）
    h1.lg-h1                 大标题
    p.lg-lead                一句话摘要
    .lg-meta                 最后更新 / 版本 / 适用于
  </div>
  <div class="lg-grid">      目录 + 正文两栏
    <aside class="lg-toc">   左侧粘性目录
      .lg-toc__title
      nav.lg-toc__list       8 个锚点
      .lg-toc__foot          指向另一份文档的提示
    </aside>
    <article>
      section.lg-sec ×8      正文各节
      .lg-foot               相关文档 + 回到注册 + 返回首页
    </article>
  </div>
</main>
<a class="lg-top">           返回顶部（滚动后出现）
```

### 3.1 为什么选方案 A

评估过三种版面：

| 方案 | 内容 | 结论 |
| --- | --- | --- |
| **A（选定）** | 左侧粘性目录 232px + 右侧正文窄栏 | Stripe、Linear、GitHub 的通用做法。8 节内容必须可定位、可分享锚点链接 |
| B | 单栏居中 760px + 顶部目录卡片 | Apple、Mozilla 的做法，阅读连贯但长文档定位需回顶部 |
| C | 要点摘要卡 + 折叠分节 | 移动端省力，桌面端阅读连贯性弱 |

用户已确认方案 A。

### 4.3 必须写进内容的产品事实

以下事实来自 `PRODUCT.md` 与现有实现，文案必须与之保持一致，不得写成通用模板：

1. 学生资料含学校、学院、专业、年级、技能标签；教师资料含任职单位、院系/部门、专业领域、职称、研究方向、导师简介，**不含年级**。
2. 教师注册后立即获得导师身份与档案，不再显示「申请成为导师」；资料完整后自动公开。
3. 公开列表与详情允许匿名浏览；申请、写入、后台操作与成果附件下载要求登录。
4. 团队空间是组队后的工作台，用于任务、里程碑、成员协作、附件和沟通。
5. **已读回执与成员在线状态是明确不提供的能力**，文案中不得暗示存在。

| 文档头 | `padding-bottom: 26px` / `margin-bottom: 34px` / 下边框 1px |

| 目录粘性 | `position: sticky; top: 124px`（64px 头部 + 60px 余量） |
| 正文节间距 | `padding-bottom: 34px` / `margin-bottom: 34px` / 分隔线 1px，最后一节无分隔线 |

| 页面纵向内边距 | 上 44px / 下 72px |

避免卡片套卡片与大面积悬浮效果（`PRODUCT.md` 卡片原则）：正文区不使用卡片容器，只用分隔线分组；仅提示块与目录在移动端降级时使用表面背景。

### 5.4 目录（scrollspy）

- 左侧 1px 竖线为轨道，当前项左侧 2px 深色竖条 + 文字加深加粗。
- 滚动时高亮跟随，判定阈值 `scrollY + 160px`。
- 点击锚点平滑滚动（`html { scroll-behavior: smooth }` 已由 `style.css` 提供）。
- 锚点 id 使用 `s1`–`s8`（隐私政策）与 `t1`–`t8`（用户协议），避免两页 id 冲突。

### 5.5 返回顶部

- 直径 40px 圆形按钮，`position: fixed`，仅滚动超过一屏后淡入。
- 位置必须**避让意见反馈悬浮按钮**。实测 `feedback.css`：桌面端 `.fbk-fabs` 为 `right: 24px; bottom: 24px`，两个 52px 按钮纵向排列、间距 12px（总高 116px），顶边在距底 140px 处；`≤767.98px` 时按钮降为 46px、`right/bottom` 变 16px（总高 104px），顶边在距底 120px 处。因此返回顶部按钮：

  | 断点 | 定位 |
  | --- | --- |
  | 桌面 `>767.98px` | `right: 24px; bottom: 152px` |
  | 移动 `≤767.98px` | `right: 16px; bottom: 136px` |

- 键盘可聚焦，`:focus-visible` 使用 `--ui-ring`。

| 断点 | 行为 |
| --- | --- |
| 桌面 `>1024px` | 232px 目录 + 正文，目录粘性 |
| 平板 `861–1024px` | 目录收窄至 200px，`gap: 36px` |

## 7. 实现要点

### 7.1 样式层

新建 `src/main/resources/static/css/legal.css`，**内容包进 `@layer pages { … }`**。

`layers.css` 已声明 `@layer vendor, legacy, tokens, base, components, pages, utilities, overrides;`，而全部存量 CSS（含 `bootstrap.min.css`）都包在 `@layer legacy` 内。因此 `pages` 层的规则天然优先，**不需要 `!important`**。

类名统一使用 `lg-` 前缀（已确认全站无 `.lg-` 冲突）。

### 7.2 脚本

新建 `src/main/resources/static/js/legal.js`，只做两件事：

1. 目录滚动高亮（读取 `.lg-toc__list a`，无依赖）。
2. 返回顶部按钮的显隐与滚动。

无第三方依赖（不依赖 Bootstrap、jQuery、GSAP）。两页各引入一次。

### 7.3 样式入口

**不修改** `fragments/head-assets.html`。

`core` fragment 被全站页面共用，在其中加入 `legal.css` 会让所有页面多下载一个仅两页使用的样式文件。因此按项目既有惯例（`team-market.html` 引入 `team-market.css`、`competitions.html` 引入 `competitions.css`），在 `privacy.html` / `terms.html` 各自的 `<head>` 中单独引入：

```html
<th:block th:replace="fragments/head-assets :: core(bootstrap=true)"></th:block>
<link th:href="@{/css/legal.css}" rel="stylesheet">
```

脚本同样在 `</body>` 前单独引入：

```html
<script th:src="@{/js/legal.js}"></script>
```

### 7.4 保留项

- 保留 `body` 上的 `data-app-page="legal"`、`class="ilink-page-bg"` 与 `data-user-id` 属性。
- 保留 `fragments/header :: header(${currentUser}, '')` 与 `fragments/head-assets :: core(bootstrap=true)`。
- 保留底部「回到注册」（`/register.html`）与「返回首页」（`/index.html`）两个按钮，样式复用 `.lg-btn--p` / `.lg-btn--s`。
- 保留 `bootstrap.bundle.min.js` 与 `common.js` 的引入。

### 7.5 打印

增加最小 `@media print` 规则：隐藏头部、目录、返回顶部按钮与底部操作区，正文改为全宽黑字。法务文档被打印或另存为 PDF 是真实场景，成本极低。

## 8. 可访问性

- 目录使用 `<nav>` + 锚点链接，键盘可达。
- 返回顶部按钮为 `<a>` 并提供 `title` 与可见焦点。
- 正文文字对比度：`--ui-text-secondary` 在 `--ui-canvas` 上满足 WCAG AA。
- 尊重 `prefers-reduced-motion`：目录平滑滚动与返回顶部滚动在减少动效时改为瞬时跳转。
- 状态标签始终带文字，不依赖颜色单独表意。

## 9. 验收标准

1. 两页在桌面端呈现为「左侧粘性目录 + 右侧正文」，目录随滚动高亮当前章节。
2. 文档头显示类型标签、标题、一句话摘要与「最后更新 / 版本 / 适用于」。
3. 两页各 8 节，锚点链接可直接跳转并在新标签页打开时定位正确。
4. 目录页脚的相关文档链接可互相跳转。
5. 860px 以下目录降级为顶部卡片，无横向溢出。
6. 返回顶部按钮不与意见反馈悬浮按钮重叠。
7. 全站其他页面的视觉与行为无任何变化（`.lg-` 前缀无冲突，样式仅在两页加载）。
8. `mvn -q -DskipTests compile` 通过；现有测试全绿。
