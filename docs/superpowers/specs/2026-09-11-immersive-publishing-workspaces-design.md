# 文章与成果沉浸式发布工作台设计

## 背景

交流社区“写文章”和成果展示“发布成果”目前位于高度受限的弹窗内。标题、分类、编辑器和附件共用弹窗纵向空间，导致 Markdown 编辑区过矮、存在嵌套滚动，长内容编写与预览困难。

## 目标

- 将文章与成果发布入口改为独立的沉浸式编辑页面。
- 让 Markdown 编辑区占据页面主要空间，消除弹窗内部滚动。
- 统一新建与编辑体验，复用已有上传、预览和保存逻辑。
- 保持现有视觉语言、接口格式和权限边界不变。

## 页面与路由

### 交流社区

- “写文章”跳转至 `/profile-article-edit.html`，没有 `id` 时为新建模式。
- `/profile-article-edit.html?id={id}` 保持文章编辑模式。
- 页面根据模式显示“写文章”或“编辑文章”，主按钮显示“发布文章”或“保存修改”。

### 成果展示

- “发布成果”跳转至 `/profile-asset-edit.html`，没有 `id` 时为新建模式。
- `/profile-asset-edit.html?id={id}` 保持成果编辑模式。
- 页面根据模式显示“发布成果”或“编辑成果”，主按钮显示“发布成果”或“保存修改”。

原发布弹窗及其入口事件不再使用，避免两套发布界面继续并存。

## 页面布局

### 桌面端

- 页面顶部设置精简的粘性操作栏，包含返回入口、页面标题、保存状态和主操作按钮。
- 内容区使用主编辑区与右侧信息栏的双栏布局。
- 主编辑区承载 Markdown 工具栏、模式切换、编辑与预览面板，占据可视区域的大部分宽度。
- 右侧信息栏集中放置标题、分类、附件以及必要的说明信息。
- 编辑器最小高度根据视口计算，使正文区域在常见桌面尺寸下占据一屏的大部分空间。

### 成果双正文

- 成果描述和竞赛心得在主编辑区内使用标签切换。
- 每个标签拥有独立的 Markdown 源码、模式状态和实时预览。
- 切换标签不会丢失输入内容；竞赛心得继续保持可选。

### 平板与手机

- 中窄屏改为单列布局，信息栏移到编辑器上方。
- 手机端隐藏分栏模式，默认显示编辑视图，可手动切换预览。
- 粘性操作栏和主要按钮满足触摸尺寸，页面不产生横向滚动。

## 数据流

### 新建文章

1. 页面无 `id` 时初始化空表单。
2. 发布时使用现有 Markdown 安全渲染和源码标记流程。
3. 调用现有文章创建接口。
4. 成功后进入新文章详情页。

### 编辑文章

1. 页面有 `id` 时加载文章及附件。
2. 保留现有附件上传、移除与同名替换行为。
3. 调用现有文章更新接口。
4. 成功后进入文章详情页。

### 新建成果

1. 页面无 `id` 时初始化空表单和两个 Markdown 编辑区。
2. 发布时沿用现有成果 `FormData` 上传格式、源码双段编码和原文件名处理。
3. 调用现有成果创建接口。
4. 成功后进入新成果详情页。

### 编辑成果

1. 页面有 `id` 时加载成果信息、成果描述、竞赛心得和附件。
2. 调用现有成果更新接口。
3. 成功后进入成果详情页。

## 状态与异常处理

- 保存或附件上传进行中时禁用主操作按钮，防止重复提交。
- 页面显示“上传中”“正在发布”“正在保存”等明确状态。
- 接口失败时保留所有输入和已上传附件，并显示错误提示。
- 表单校验失败时定位并聚焦首个错误字段。
- 用户修改内容后离开页面时显示未保存确认；成功保存后取消拦截。
- 不增加自动保存或草稿功能，避免扩大本轮范围。

## 兼容与清理

- 继续使用统一 Markdown 渲染、DOMPurify 清洗和源码恢复逻辑。
- 继续使用现有附件上传、同名替换、原文件名和文件类型图标能力。
- 移除发布弹窗相关的无用 DOM、样式绑定和事件初始化，保留编辑器公共组件。
- 成果详情附件卡片按已确认的独立规格同步改为社区同款紧凑卡片。

## 验收标准

1. 点击“写文章”和“发布成果”均进入独立页面，不再打开弹窗。
2. 新建和编辑共用同一页面，标题和主按钮随模式正确变化。
3. 桌面端编辑器明显扩大，无弹窗内部滚动，分栏编辑与预览可正常使用。
4. 成果描述和竞赛心得可以通过标签切换，内容互不丢失。
5. 文章和成果的新建、编辑、附件上传、同名替换、预览、保存均正常。
6. 保存成功后进入对应详情，发布效果与预览一致。
7. 保存失败不会清空输入；上传或保存中不会重复提交。
8. 未保存离开确认正常，成功保存后不再误提示。
9. 桌面、平板和手机均无横向溢出，手机可在编辑与预览间切换。
10. 成果详情附件展示符合社区详情附件卡片规范。
