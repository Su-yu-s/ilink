# 办公文件工作流

## 先判断交付物类型

| 用户想要 | 用 |
|---|---|
| 写清楚一件事、给材料、留档 | docx |
| 管任务、排期、清单、评分 | xlsx |
| 讲给别人听、答辩、汇报 | pptx |
| 定稿提交、打印、防篡改 | pdf |

一次交付可以包含多个文件，但每份只承担一种职责。

## 标准流程

1. **先查事实**：涉及团队任务、成员、竞赛信息时，先用 `kg_*` 工具查证，不要凭记忆写。
2. **再定结构**：按场景选模板（见各 skill 的“常用结构”）。
3. **生成文件**：调用 `office_generate`，只传结构化内容。
4. **核对结果**：检查文件名、大小、条目数；需要时重新生成。
5. **等用户确认**：文件在沙箱里，未确认前不会进入团队资料库。

## 模板填充

已有正式模板（报名表、计划书、答辩 PPT）时，优先填充而不是从零生成：

```json
{
  "format": "docx",
  "title": "报名表-2026",
  "templatePath": "报名表模板.docx",
  "replacements": { "projectName": "iLink", "leader": "张三", "date": "2026-11-03" }
}
```

- 模板放在 workspace 内，占位符写成 `${key}`。
- 占位符必须是连续文本；在 Word 里给 `${key}` 中间切换加粗/颜色会导致拆分，替换不命中。
- 填充保留模板样式，但不会新增段落；需要额外内容时先用模板生成，再单独追加文档。
- 模板里没有任何占位符会直接报错，不会静默生成空文档。

## 更新已有文件

资料库里已有同名文件时，用 `library_propose_update` 替换，而不是重复上传：

- 新文件放在 workspace，文件名可以不与旧文件完全一致，服务端会沿用旧文件名。
- 旧文件进入回收站，可在资料库回收站恢复。
- 用户确认前不会生效。

## 组合交付示例

### 周报

- `周报-2026-11-03.docx`：本周完成、风险、下周计划
- `任务台账.xlsx`：任务 / 负责人 / 状态 / 截止
- 汇报时用 `周会.pptx`（3–5 页）

### 竞赛报名

- `报名表.docx`：基本信息 + 签字页
- `材料清单.xlsx`：材料名 / 是否已备 / 负责人
- `参赛材料.pdf`：按清单顺序合并的定稿

### 答辩

- `答辩讲稿.docx`：完整讲稿
- `答辩演示.pptx`：结论与数据
- `项目计划书.docx`：供评委查阅

## 文件命名

`<主题>-<版本或日期>.<扩展名>`，例如：

- `项目计划书-2026-11-03.docx`
- `任务台账-第8周.xlsx`
- `答辩演示-v2.pptx`

不使用空格、括号、斜杠；中文与数字之间不加空格。

## 事实与来源

- 文件里的任务、成员、竞赛信息必须来自 `kg_*` 工具或当前团队事实。
- 无法核实的数字写成“待确认”，不要编造。
- 引用原文时保留 `r#` / `c#` 编号，便于复核。

## 禁止事项

- 不生成带宏的文件（`.docm` / `.xlsm` / `.pptm`）。
- 不把密钥、令牌、身份证号、手机号写入任何文件。
- 不在未确认的情况下声称文件“已上传”或“已入库”。
- 不用文件替代任务系统：创建任务仍需走确认后的动作提案。
